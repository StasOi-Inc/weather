# Weaser

Android-приложение: агрегированный прогноз осадков на ближайшие 24 часа.
Собирает почасовые прогнозы у нескольких сервисов, накапливает статистику их точности
именно для вашей локации (Brier score, MAE, hit rate) и взвешивает источники по точности.
Без сети работает на кэше с пометкой «данные от HH:MM».

## Стек

Kotlin, minSdk 26, Jetpack Compose + Material 3 (динамические цвета), Glance (виджет),
Hilt, Retrofit + kotlinx.serialization, Room, WorkManager, MapLibre GL (карта радаров),
Compose Canvas (графики). Агрегатор и метрики — чистый Kotlin без Android-зависимостей.

## Сборка

Требуется JDK 17 и Android SDK (compileSdk 35).

```bash
gradle wrapper --gradle-version 8.9   # если нет gradlew
./gradlew :app:testDebugUnitTest      # юнит-тесты метрик и агрегатора
./gradlew :app:assembleDebug          # app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:assembleRelease        # релизный APK (minify + shrinkResources)
```

В Android Studio достаточно открыть папку проекта и нажать Run.

## Ключи API (local.properties, в репозиторий не попадают)

Обязательных ключей нет: без ключей работают Open-Meteo (прогноз + геокодинг + анализ факта),
MET Norway (User-Agent задаётся приложением) и RainViewer (радары).

Опциональные:

| Ключ | Источник | Статус |
|---|---|---|
| `openweathermap.key` | OpenWeatherMap, бесплатная регистрация; используется `data/2.5/forecast` (5 дней / 3 часа) | опциональный |
| `weatherapi.key` | WeatherAPI.com, бесплатная регистрация | опциональный |
| `yandex.key` | Яндекс Погода. Бесплатный тариф закрыт (архивный); остались платные подписки от 54 000 ₽/мес через Yandex Cloud Marketplace и 7-дневный пробный период в кабинете «Погода для бизнеса». Источник активен только с оплаченным ключом, приложение от него не зависит | строго платный |
| `gismeteo.key` | Гисметео, коммерческий API; контракт требует сверки с официальной партнёрской документацией перед включением. Без ключа скрыт | строго платный |

Пример `local.properties`:

```
sdk.dir=C:/Android/sdk
openweathermap.key=xxxx
weatherapi.key=yyyy
```

Ключи попадают только в `BuildConfig` и никогда не хардкодятся в коде.

## Архитектура

- `domain/` — модели, интерфейс `WeatherProvider`, метрики (`Metrics`), калькулятор весов
  (`WeightCalculator`), агрегатор (`PrecipitationAggregator`), детектор интервалов осадков.
- `data/remote/` — Retrofit-адаптеры источников; новый источник = один класс-адаптер
  + добавление в `ProviderRegistry` в `di/NetworkModule.kt`, без правки ядра.
- `data/local/` — Room: `forecast_snapshots` (каждое обновление пишет снапшоты всех источников,
  включая сырой JSON), `observations` (факт из анализа Open-Meteo), `source_state`, `source_metrics`.
- `data/repository/` — синхронизация: параллельный опрос активных источников с суммарным
  таймаутом 10 секунд; упавший источник не влияет на остальные; агрегация и запись кэша.
- `presentation/` — Compose: «Сейчас/24 часа», «Источники» (веса, точность, статусы, вкл/выкл),
  «Радар» (RainViewer + MapLibre, таймлайн факт ~2 ч + nowcast ~30 мин).
- `widget/` — Glance-виджет (4×1, растягивается), обновление через WorkManager,
  переживает перезагрузку устройства.
- `work/` — синхронизация раз в 30 минут; адаптивно раз в 15 минут при высокой вероятности
  осадков в ближайшие 2 часа; пересчёт метрик/весов — раз в сутки.

## Приватность

Координаты округляются до 2 знаков перед отправкой в API. Геолокация — только по явному
действию пользователя. Аналитики и трекеров нет.

## Принятые решения

- OpenWeatherMap: One Call 3.0 требует подписки, поэтому используется 5-day/3-hour.
- MET Norway: в compact-формате probability_of_precipitation может отсутствовать — в этом
  случае вероятность оценивается по интенсивности.
- Яндекс Погода: время часов приводится к таймзоне устройства (API не отдаёт utc offset).
- Гисметео: адаптер-каркас; эндпоинт/параметры сверяются с официальной документацией
  при подключении ключа, до этого источник возвращает ошибку.
- Виджет: один ресивер 4×1 с вертикальным resize (вместо двух отдельных).
- Подтверждение факта осадков радарами RainViewer (п. 4.5 ТЗ) в v1 не реализовано:
  факт берётся из почасового анализа Open-Meteo (past_days=1).
- Веса: обратная ошибка (1 / (brier + ε)) на скользящем окне 30 дней с экспоненциальным
  затуханием (полураспад 15 дней); холодный старт — равные веса с пометкой в UI.
- Разброс источников: стандартное отклонение вероятностей > 25 п.п. — плашка «Источники
  расходятся» с диапазоном [min, max].

## Известные ограничения

- CI: сборка проверяется в GitLab (см. `.gitlab-ci.yml`); локальная сборка требует Android SDK.
- Базовое покрытие территории РФ обеспечивают Open-Meteo, MET Norway и OpenWeatherMap —
  без платных ключей.
- Прогноз длиннее 24 часов, push-уведомления, синхронизация устройств — вне объёма v1.
